# Heartbeat (every 20 minutes, every check; owner 2026-11-06)
FLEET = <harness>, repo <repo>. Run every check below, in order, one foreground call each, small output only. First measure the pipeline: run <FLEET>/bin/dashdata.py and read <FLEET>/dash/pipeline.json; the first line of the result and of the hand-back is always `proven X, landed Y, waiting-land Z, in review W` (functions; add `building V` and the packet counts after it), then, on the same line, the gate checklist from <FLEET>/dash/gate.json: `gate <gate> <done>/<n>: <condition> <value> done|open; ...; next: <first open condition> (<packet>)`. Never launch agents, never edit briefs, code, thresholds or protected files.
0. Management (first, so the call cap never cuts it): do <FLEET>/templates/management.md over briefs and FAIL reviews written since the newest <FLEET>/reviews/management-*.md; write its file there.
0b. MANAGING verdict, every heartbeat: measure (a) proven on deployed main vs the previous heartbeat, (b) gate merges in the last hour, counted only after `git fetch` (an unfetched count reads 0), (c) each open phase-gate item and whether an agent or the gate bot owns it, (d) agents on off-critical-path work while an item is unowned, (e) any check over 25 min stale. First line: `MANAGING: GOOD` only if proven on deployed main rose in the last 3 hours of a build phase (merges alone are not good: a fleet ran 60 merges in 7 hours with proven flat and was rated GOOD every heartbeat, 2026-11-07); flat for 3 hours is `MANAGING: BAD - busy, not finishing - FIX: launch the missing pieces of the function nearest proven`; master-status.py and the Stop hook block the master's turn until a red-fix newer than that heartbeat exists.
1. Health: `py -3 <repo>/tools/health/health.py`; list the newest run's red tripwires with their action column.
2. Machines and burn: `py -3 <FLEET>/bin/heartbeat.py`; list its new red rows.
3. Rows: from the repo run `py -3 <repo>/tools/vc/vc.py dispatch-sync` once (vc may not be on PATH). Loop status: `py -3 <FLEET>/bin/master-status.py`; copy its lines.
4. Bottleneck: read the `top` of <FLEET>/dash/bottleneck.json and the last RULINGS.md line naming that stage; say whether the stage's wait dropped since that fix.
6. Dashboard: the master launches dash-refresh and red-fix after your hand-back, so the dashboard carries this run's management time; only check <FLEET>/dash/.uploaded is under 25 min old and say red if not.
Write the whole result to <FLEET>/heartbeat/<UTC yyyy-mm-ddTHHMM>.md. Hand back at most 7 lines: the pipeline line first, then one per check, red items first, each with the action it calls for. Call cap 45.

0c. QUALITY, every heartbeat (owner 2026-11-07: "you should already know the answer, this is your job as the manager"): tally post-merge sample audits from the last 12 h (pass, real-bug fail, paper fail), main's lint findings by id (duplicates and cross-owner imports), and the newest blind code-quality score; write one QUALITY line second in the result, append it to FLEET/QUALITY.tsv, and turn any real bug or duplicate on main into a fix packet the same run.
